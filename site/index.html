Why it exists

One agent is easy. Five becomes a second job.

  1. Tabs, not a team.

    Every agent lives in its own terminal. Nothing tells you which one is waiting on you, which one is stuck, and which one finished an hour ago.

  2. Context dies with the session.

    A fresh session starts from zero, so you re-explain the repo, the decision, and the dead ends you already ruled out.

  3. One account, one ceiling.

    A single rate limit stalls the whole afternoon while another account you already pay for sits idle.

How it works

From first launch to reviewed work.

A supervising daemon runs the agents. The desktop app and any MCP client are two ways to drive the same thing.

  1. 01

    Connect a provider

    A fresh install starts with no accounts. The first screen walks you through connecting Claude, Codex, Kimi or any OpenAI-compatible endpoint.

  2. 02

    Shape a team

    Define roles — an implementer, a reviewer, whatever the repo needs — and bind them to a queue with a concurrency cap.

  3. 03

    Queue the work

    Push tasks with priorities and dependencies. Each agent picks one up in its own git worktree, so five of them never fight over one working tree.

  4. 04

    Review what came back

    Gates decide whether a step passes: a shell command, an artifact check, a human approval or a critic loop. You review results instead of watching terminals.

Queues and workflows

A queue that knows what blocks what.

Tasks carry a priority and, when order matters, a dependsOn list. A dependent task waits until the work it needs is done — and fails with it if that work fails.

Task lifecycle

  1. pending
  2. running
  3. done
blocked
Waiting on a dependency. Cascades to failed if that dependency fails.
failed
The attempt ended in error. Retries are configurable per queue.

Gates a step can use

  • Shell command — pass or fail on an exit code.
  • Artifact check — a report, diff or file the agent produced.
  • Human approval — pause until someone says yes.
  • Critic loop — an evaluator sends work back until it holds up.

Shared memory

Notes that outlive the session.

One agent leaves a fact, a decision or a todo. Any other agent — or a session that starts tomorrow — finds it again instead of being told twice.

  • Hybrid search: lexical and semantic, ranked together.
  • [[wiki-links]] build a backlink graph between notes.
  • Notes carry a kind, an author, a team and a project.

Scoping is a ranking default, not an access boundary: any agent can widen a search.

Availability

Early access, on a Mac first.

One command installs the signed desktop app and the CLI on macOS and Linux.

macOS · Apple Silicon
SupportedSigned and notarized; the most tested platform.
macOS · Intel
Less testedSigned and notarized build, not yet verified on a clean machine.
Linux · x64 / arm64
PackagedAppImage installed by the same command; not yet verified end to end. Browser tools are unavailable on Linux arm64.
Windows
CLI onlyThe CLI and MCP server install with npm; the desktop app waits for a code-signing certificate.

Desktop control is macOS-only. The optional local decision model (Laya) needs macOS 14 or newer and downloads one pinned English model when you install it, so a fresh install is not fully offline. After that it runs offline, and multilingual requests fail rather than fetch an unreviewed model.

Install

One command.

Needs Node.js 24+ (which includes npm) and Git. macOS and Linux.

npx @nedimyilmaz/chimera install

Downloads the signed desktop app, verifies its SHA-256, installs the app and the chimera CLI, starts the daemon at login and opens the app, which walks you through connecting a provider. --dry-run shows what it would do; --no-open skips opening the app.

curl -fsSL https://raw.githubusercontent.com/nedimYilmaz/chimera/main/scripts/install-public.sh | bash

The same install without npx. For only the CLI and MCP server (any OS, including Windows): npm install --global @nedimyilmaz/chimera.

Questions

Before you try it.

Can I install it today?

Yes. npx @nedimyilmaz/chimera install installs the signed desktop app and the CLI on macOS and Linux. macOS on Apple Silicon is the best-tested path.

Does it run on Windows?

The CLI and MCP server do (npm install --global @nedimyilmaz/chimera). The desktop app does not yet: it waits for a code-signing certificate, and the installer stops before downloading anything on Windows.

Does it work offline?

The daemon and the app run locally, but your agents call the providers you connect, so they need a network. One built-in extra is a download: the optional local decision model (Laya) fetches one pinned English model when you install it, so a fresh install is not fully offline. After that Laya runs offline.

Which agents does it work with?

Claude (through the Claude Agent SDK), Codex (SDK and app-server), Kimi (over the Agent Client Protocol) and any OpenAI-compatible chat endpoint. Claude and Codex have seen the most use; the Kimi backend and federation are younger, and voice is a preview.

Is it safe to point at my repo?

Each agent gets its own git worktree, so agents do not collide in one working tree. A worktree isolates changes, not processes or filesystem access: an agent with full access can modify anything your OS user can. Pick readOnly, acceptEdits or full per agent, keep full for trusted work, run Chimera as your regular user and keep the daemon on local IPC.

Does it replace Claude Code or Codex?

No. It supervises them. You can also drive Chimera from inside Claude Code, Codex or any stdio MCP client, so one agent can coordinate others.

Where does my data go?

Chimera is a local daemon with local storage in ~/.chimera; there is no hosted service. Your prompts go to whichever provider you connect, under that provider's terms.
